v21.8.10
  - The programme guide loads much faster on a TV box. Measured on the Android
    box, a full refresh spent about 85% of its time not fetching anything:
    Kodi asks for the guide one channel at a time and does its own work on each
    answer, and it was being handed all ten days -- roughly 93,000 programmes
    -- every single time. Kodi never drops a programme because the add-on
    stopped sending it, so once it has been given the history the refresh now
    carries only the last day of it plus the future, which is about 60% less
    for both sides to do. The whole window is still delivered on the first
    refresh, after the channel line-up changes, when more past days are put on
    display, and again once the history Kodi was given would have aged out of
    the guide on its own
  - The first channels of a refresh no longer wait on a batch of fifteen. Kodi
    walks the guide faster than full-size requests come back, and the first two
    channels it asked for were costing it 5.7 and 5.1 seconds of waiting; the
    prefetch now starts with small requests and grows them
  - Reading an age rating no longer throws an exception per programme, and HTTP
    responses are no longer reassembled as C strings, one strlen() per 16KB

v21.8.9
  - The programme guide loads about four times faster. Kodi asks for the guide
    one channel at a time and waits for each answer, so a full refresh was one
    HTTP round trip per channel -- 289 of them on a Telemach line-up. The
    backend answers a request for up to 15 channels at once, so the first
    channels of a refresh now start a background prefetch that pulls the whole
    guide in batches of 15 across four threads, and every channel is then
    answered from memory. Measured on macOS over a ten day window, a full
    refresh went from 20 seconds and 289 requests to 5 seconds and 20. It
    transfers the same amount of data either way -- the saving is the round
    trips, not the bytes

v21.8.8
  - A programme played from the guide now shows its own length. It was being
    presented with the timeline live TV gets -- from the programme's start
    until now -- so a 30-minute episode that aired six hours ago read as
    00:06:16 / 06:19:24 with the progress bar barely off its left edge. A
    programme that is still on air keeps growing as before, and playback still
    carries on past a finished programme into whatever airs next

v21.8.7
  - Fix live rewind being unavailable on the first channel played after opening
    Kodi. The first request made once the stored access token has expired comes
    back 401, and the retry that follows the token refresh was rebuilt with only
    an Authorization header -- it dropped the User-Agent, the content type, and
    the header that tells the EPG endpoint its time arguments are epoch
    milliseconds. When that retried request was the tune-in's "what is on now"
    lookup, the backend rejected it, the channel had no programme window, and it
    played as a plain live stream with nothing to rewind into. Switching channel
    appeared to fix it only because by then the token was valid and no retry was
    needed

v21.8.6
  - Channel start is no longer held up for several seconds. Two of the requests
    every tune-in made existed only to write diagnostic lines into the log, and
    they fetched the playlist on the very session URL that was then handed to
    the player -- so the player joined a session whose opening playlist window
    had already been served, and had to wait for the next segment to be
    published before it could show anything. Those fetches now sit behind a
    setting (Streaming -> "Log stream diagnostics", off by default). Measured
    on macOS, a channel starts in about 0.6 seconds where it used to take
    about 6.4
  - Two further requests are gone from the tune-in path: the current time is
    now derived from the backend/device clock offset, re-measured every 15
    minutes rather than fetched for every URL, and the "what is on now" lookup
    is remembered per channel for as long as that programme is still on air.
    Seeking gains from the first of those too -- the seek proxy used to fetch
    the time before it could mint each URL

v21.8.5
  - Fix being unable to return to live TV from the guide: while a replay show
    was playing, selecting the channel's currently airing programme did
    nothing at all. Replay is opened as an EPG-tag playback session again
    rather than claiming the channel session, which is what made Kodi treat
    the channel as already playing live and skip the re-tune. Trade-off: the
    displayed title stays pinned to the selected show if playback continues
    past its scheduled end (progress and seeking stay correct)
  - Fix "playback failed" when two stream opens overlap. The local seek proxy
    was torn down and relistened on a fresh port for every new stream, which
    left the open already in flight pointing at a dead port. It now keeps one
    port for the add-on's lifetime and tracks each stream as its own session,
    so concurrent opens no longer invalidate each other. Overlap is routine:
    Kodi asks for an EPG tag's stream properties twice per playback, and its
    "play next programme automatically" can fire at the same moment the user
    picks something else in the guide
  - Declare inputstream.ffmpegdirect as a dependency again so Kodi installs
    it automatically; it is the inputstream the add-on's own documentation
    tells users to select, but the import was dropped in 2023
